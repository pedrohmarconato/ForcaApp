**New components for this phase:**

| Component | Responsibility |
|-----------|-----------------|
| `src/screens/InstallScreen.tsx` | Orchestrates the 4-state render (see Copywriting Contract) |
| `src/utils/installDetection.ts` | Pure functions: `isIOS()`, `isSafari()` (excludes `CriOS`/`FxiOS`), `isStandalone()` (matchMedia + `navigator.standalone`) — already scoped by CONTEXT.md, listed here only so the UI-SPEC component list is complete |
| `StepRow` (local to `InstallScreen.tsx` or `src/components/ui/StepRow.tsx` if reused elsewhere later) | Renders one numbered step: neon badge + Feather icon + title + description — see anatomy below |

**`StepRow` anatomy (iOS + Safari state only):**

- Badge: circle, `width/height: 40` (`theme.spacing.huge`), `borderRadius: theme.borderRadius.pill`, `backgroundColor: theme.colors.veil.faint`, `borderWidth: 1`, `borderColor: theme.colors.border.focus` (neon at 45% — reuses the existing focus-ring token, do not invent a new rgba). Number text: `fontSizes.xl` (20), `fontWeights.bold` (700), `color: theme.colors.text.accent` (neon) — **this badge number is the accent use**, never fill the whole circle with solid neon (brandbook: "neon como destaque, não preenchimento dominante").
- Icon: `Feather`, `size 18`, `color: theme.colors.text.primary` (white — icon is not part of the accent budget), placed inline before the step title.
  - Step 1 ("Compartilhar"): `icon="share"`
  - Step 2 ("Adicionar à Tela de Início"): `icon="plus-square"`
  - Step 3 ("Adicionar" / confirmar): `icon="check-circle"`
- Title: `fontSizes.lg` (16), `fontWeights.semiBold` (600), `color: theme.colors.text.primary`.
- Description: `fontSizes.lg` (16), `fontWeights.regular` (400), `lineHeight: 16 * theme.typography.lineHeights.normal` (24), `color: theme.colors.text.secondary`.
- Row spacing: `gap: theme.spacing.lg` (16) between badge and text block; `marginBottom: theme.spacing.xxl` (24) between rows (last row: 0).

## Spacing Scale

This phase does **not** introduce a new scale — it reuses the project's existing token ladder (`src/theme/theme.ts`, `spacing`), which predates this phase and is not the generic 8-point scale from the template default. Documented here so the executor never invents a raw pixel value:

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| xxs | 4px | Micro gaps (badge number optical centering) |
| sm | 8px | Icon-to-title gap in `StepRow`, chip padding |
| md | 12px | Compact internal padding (state `Notice` internal spacing — inherited from `Feedback.tsx`) |
| lg | 16px | `StepRow` badge-to-text gap; card horizontal padding on narrow viewports |
| xl | 20px | Outer screen padding (`ScrollView` contentContainerStyle, same as `AuthLayout.scroll`) |
| xxl | 24px | Card internal padding; gap between `StepRow`s; gap between headline block and step list |
| xxxl | 32px | Gap between brand lockup and headline block |
| huge | 40px | `StepRow` badge diameter; minimum touch-adjacent breathing room around the CTA button in the standalone state |

Exceptions: none beyond the inherited ladder above (project scale includes 6/12/20/40, which are not multiples of 8 — this is the existing system-wide convention, not a new exception introduced by this phase).

## Typography

Reuses `theme.typography` tokens exactly — no new font size or weight is introduced. Only 3 distinct sizes and 2 weights are used in this phase (holds the contract's 3–4 size / 2 weight ceiling even though the shared `theme.ts` defines more sizes for the app at large):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (page headline, e.g. "Instale o ForçaApp no seu iPhone") | 24px (`fontSizes.display`) | 600 semiBold | 1.15 (`lineHeights.tight`) |
| Heading (`StepRow` title, state block title) | 16px (`fontSizes.lg`) | 600 semiBold | 1.35 (`lineHeights.snug`) |
| Body (`StepRow` description, state block body — generous, leigo-friendly, deliberately larger than the app's default 12px body) | 16px (`fontSizes.lg`) | 400 regular | 1.5 (`lineHeights.normal`) |
| Label (eyebrow/tagline above headline, "Instalado" success chip) | 9px (`fontSizes.micro`) | 600 semiBold, uppercase, `letterSpacing.wider` (1.6) | 1.35 (`lineHeights.snug`) |

Rationale for size 16 on both Heading and Body: hierarchy comes from weight (600 vs 400), not size — matches the existing system principle ("padrões consistentes... mesma geometria e escala") and keeps every readable line at the generous size CONTEXT.md requires for a leigo audience (no 11–12px body text anywhere on this page).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0A0A` (`theme.colors.surface.canvas`) | Screen background |
| Secondary (30%) | `#171A1D` (`theme.colors.surface.card`) | Page card (same frame as `AuthLayout.card`), `StepRow` container if boxed |
| Accent (10%) | `#EBFF00` (`theme.colors.accent.main` / `theme.colors.text.accent`) | Listed exhaustively below — never a background fill |
| Destructive | `#DC827B` (`theme.colors.status.danger`) — reserved, not used in this phase | No destructive action exists on `/instalar`; token declared only for completeness |

**Accent reserved for (explicit list — nothing else may use neon on this page):**

1. The digit inside each `StepRow` badge (1, 2, 3) — iOS + Safari state only.
2. The checkmark icon inside the "Instalado" success badge — standalone state only.
3. The single primary CTA button fill ("Abrir o ForçaApp") — standalone state only, `variant="primary"` per `Button.tsx`'s existing rule of at most one neon-filled button per block.

These three uses are mutually exclusive per state (a given render of the page never shows more than one of them at a time), so the "one neon fill per block" system rule is never at risk of being violated.

## Focal Points (primary visual anchor per state)

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).

Elements classified: `install-steps` (list-collection, State 1 only), `state-block` (static-content, States 2–4), `cta-abrir-app` (interactive-control, State 4 only).

Applicable state considerations resolved: 7 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | install-steps | ✅ covered | `install-steps` is a literal fixed-length array of 3 items defined in source, not derived from any external/loaded data — it can never render empty. |
| loading | install-steps, cta-abrir-app | ✅ covered | State detection (`isIOS`, `isSafari`, `isStandalone`) runs synchronously on first render via `matchMedia`/`navigator.userAgent` — no network call, no async gap, so no loading/skeleton state is needed anywhere on this page. |
| error | install-steps, cta-abrir-app | ✅ covered | An absent/atypical `navigator.userAgent` (exotic browser) falls through to the State 3 branch ("Desktop/Android → abra no iPhone") as the safest generic default — it never fakes the iOS+Safari happy path on unrecognized input. There is no dedicated error screen because there is no network request that can fail. |
| populated | install-steps | ✅ covered | Happy-path content is exactly the 3-step sequence (Compartilhar → Adicionar à Tela de Início → Adicionar) with the literal copy in the Copywriting Contract above. |
| partial | install-steps | ✅ covered | The steps array is a fixed literal in source; there is no partial-data source that could leave a step incomplete. |
| overflow | state-block (State 3 URL display) | 🧪 backstop | The URL chip in State 3 must wrap rather than clip on narrow viewports (iPhone SE 375px, small Android): standard RN `Text` wrapping (`flexWrap`, no `numberOfLines`), no horizontal scroll. Needs a held-out visual/snapshot check at a narrow width — not covered by a plain RTL text-presence test. |
| zero-one-many | install-steps | ✅ covered | Always exactly 3 items (constant); there is no 0/1/many variance and therefore no singular/plural copy branching to test. |
| long-text | state-block (all states), cta-abrir-app | ✅ covered | Every string in the Copywriting Contract is one to two short sentences; typography uses `lineHeight: normal` (1.5) with the RN `Text` default wrap behavior — no truncation or ellipsis appears in any state. |
